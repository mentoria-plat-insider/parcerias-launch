# Política de Segurança

## Comunicação responsável

Não registre vulnerabilidades, exposição de dados ou credenciais em issues públicas. Envie uma descrição privada ao responsável técnico do projeto, incluindo o impacto observado, os passos de reprodução e qualquer evidência necessária para investigação.

Se o incidente envolver dados pessoais de participantes, suspenda a divulgação ampla da evidência e siga o processo interno de resposta a incidentes aplicável.

## Escopo de interesse

Relate, entre outros, problemas de autenticação, autorização entre papéis, acesso indevido a projetos ou reuniões, vazamento de dados, manipulação de agenda, exposição de segredos e falhas na validação de entradas.

## Boas práticas do repositório

- Não versione arquivos `.env`, tokens ou dumps de banco.
- Use a revisão de pull request para mudanças de segurança.
- Execute testes, checagem de tipos e auditoria de dependências antes de integrar alterações.
- Mantenha dependências atualizadas por processo controlado.

Esta política é operacional e não substitui o processo corporativo de resposta a incidentes ou obrigações legais aplicáveis.
